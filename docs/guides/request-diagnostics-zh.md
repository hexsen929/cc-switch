# 请求详情中的完整正文

在「用量 → 请求详情」开启正文采集后，新请求的每次上游尝试都分别记录完整的脱敏请求和响应。会话轮次上限后的身份轮换重试也作为独立尝试显示，可对比原始失败响应和归档后的请求。

「完整上游请求／响应」按需从内存加载，保留历史、工具参数和结果、推理密文等字段。鉴权值仍会脱敏；JSON 空白及 SSE 的 data 行格式会规范化，不承诺与传输字节逐字节相同。页面下方的精简预览会折叠密文、缩短长文本，不再因为大请求超过预览大小而只显示占位符。

完整正文不自动写入文件或数据库。手动点击「导出已采集数据」并在系统保存对话框选择位置，才会写入该文件。关闭采集会清空内存记录；应用重启、最近 40 条记录淘汰或完整正文缓存淘汰后无法恢复。切换供应商本身不会清空记录。

每份完整正文最多 32 MiB，所有已完成正文共用 128 MiB 缓存；正在读取的响应共用 64 MiB 临时缓冲。超过容量会明确显示不可用，不把截断前缀标成完整正文。未解码或无法安全脱敏的内容同样标为不可用。中途断流时，已能安全解析的部分可作为中断数据查看；这不表示响应完整。

HTTP 200 只代表上游响应头。诊断另行显示完成、失败、未完成或传输中断事件；下次遇到轮次限制，可以先切换供应商，再查看刚才失败的尝试。只有关闭采集、重启或淘汰会使详细记录丢失。
