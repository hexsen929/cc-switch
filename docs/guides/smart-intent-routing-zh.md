# 智能意图分流

设置 → 本地路由 → 意图路由，先选 Claude Code、Codex 或 Gemini CLI，再开启该应用的意图路由与「智能意图分流」，最后保存。默认关闭，不会自行选择或测试供应商。

- 分类器：选一个已有供应商并填写它支持的模型。分类器必须能产生短文本答案。最多三个，按顺序共用一个超时预算；选远端分类器会产生真实 API 调用和费用。
- 类别：写明「简单提问、短翻译」或「排查故障、跨文件设计」等分类描述，指定供应商、模型，以及可选的推理强度。一个类别可以有多个不同供应商作为后备，只有该应用开启故障转移时才会尝试后备。分类器只能返回类别编号，不能指定地址或供应商。
- 顺序：既有本地规则先匹配。未命中才分类；分类无匹配时仍走原路由。分类失败时会尝试下一分类器，再尝试同会话上次的决定，没有可复用的结果则走原路由。显式 Stack、直连和有网关密钥授权的请求不发起分类。
- 隐私：分类器会收到本轮的可见用户文字（长文本取首尾）、上一轮用户和助手的文字节选，以及配置的类别。它不需要完整上游正文、工具结果、附件、系统提示或隐藏推理。分类请求使用所选卡片的代理鉴权及隐私过滤，不转发客户端会话头。分类缓存是有界进程内数据，不建立会话正文数据库。
- 诊断：启用代理日志后，到「用量 → 请求详情 → 诊断」看类别编号、分类器编号、耗时、缓存命中、同轮复用或回退；不必开启正文预览。分类耗时不等于回答模型的首字耗时。
- 可选「缓存仍热时保留强模型」：只影响标为复杂到简单的降档，普通自定义类别不受影响。须开启代理用量日志，而且同一会话的同一首选供应商和模型实际报告过至少 1024 个缓存 token。五分钟后、轮次缩短、或没有上述用量证据时，按本轮判断。不会为探测缓存额外请求模型。

## 嵌套路由组

在「路由组」中新建一个命名子组。可以给它设置按顺序尝试的成员，或关闭「只按成员顺序」并设置自己的分类器和类别。回到主组，在某个类别的目标中选择「路由组 · 子组名」。例如主组将“工程问题”送进“开发”，由“开发”的分类器区分“解释代码”和“排障”。成员可以是供应商加模型，也可以是另一组。可用箭头调整顺序；先解除引用才能删组。

最多 16 个命名组、包含根组在内最多 8 层。保存会拒绝缺失引用和环，包括没有挂在根组下的环。每个请求只展开命中的分支和允许的后备；重复子组只访问一次。所有组共享根组的总等待上限；无匹配、低置信度或超时可走该组的默认成员。原应用的故障转移开关、重试次数和熔断仍然有效。

要复用一组备用分类器，新建命名组后选「用作分类器池」，填入决策模型及各自的协议。然后在主组或子组的分类器栏选择这个池。池也可以引用另一个分类器池；展开后最多 16 个不同的分类器。每个候选回答同一个父组分类问题，不会把分类问题当新一轮用户请求。拒答或协议错误才试下一台，有效的“无匹配”不会重复扣费。分类器池不能作回答目标，回答组也不能冒充分类器池。

## 专用决策接口

分类器协议默认是普通聊天。也可以明确选择 **OpenAI Decisions**（`/v1/decisions`）、**System One**（`/v1/systemone`）或 **Google Decisions**（`/v1beta/decisions`）。端点从所选供应商卡的 API 基址生成；卡必须提供该协议支持的模型和静态 API Key。普通 ChatGPT、Copilot 等托管订阅的登录令牌不会发到专用端点。仅允许 HTTPS 或本机回环 HTTP，不追随重定向；不是面向外部客户端新增一个公开 API。

专用接口发送带类别选项的结构化问题，按返回的选项和置信度判断，不从自然语言里猜模型名。有效的“无匹配”和低置信度走默认成员；拒答、畸形响应、超时或接口不可用按配置尝试下一个分类器。要让不支持 Decisions 的中转站回退到聊天，可把普通聊天分类器排在后面。诊断中按组列出实际分类结果，不保存问答正文。

参考 [Magpie v0.1.4976 的分类器](https://github.com/yetone/magpie/blob/v0.1.4976/internal/gateway/classify.go)。此实现对齐上述工作流，不代表所有第三方决策网关的私有协议或真实分类结果完全一致。
